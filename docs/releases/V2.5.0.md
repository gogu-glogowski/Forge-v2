# Forge V2.5.0

Forge V2.5.0 is a Fedora-first release for persistent, managed
KVM/QEMU/libvirt VMs. It focuses on durable ownership, verified reusable bases,
explicit recovery boundaries, and practical ManualGuest workflows for a small
security-focused VM fleet.

## Highlights

- Persistent Kali Lab workflow with official-artifact verification and proven
  reusable shared bases.
- Persistent VM cloning with an independent flattened target disk.
- Fresh replacement flow for supported managed instances, preserving
  fail-closed ownership and backing checks.
- Safe managed delete: exact domain UUID and resource ownership validation,
  shared-base protection, durable delete progress, and explicit force handling
  only for a running exact VM.
- Operator-assisted Fedora Workstation preparation: verified ISO, graphical
  Anaconda installation, explicit proof checkpoints, and promotion to a
  protected canonical reusable base.
- Whonix Gateway and Workstation profiles with complementary managed topology
  and canonical pair identities.
- Stronger durable generation state, initial-create recovery, and exact
  backing/storage reconciliation.
- Image provenance and execute-time identity revalidation, including
  descriptor-pinned source handling at sensitive image-import boundaries.
- ManualGuest lifecycle cleanup: no QGA probe for a domain without a QGA
  channel, and no guest-exec, SSH, or cloud-init requirement for these paths.
- Simplified host privilege model: standard Fedora/libvirt authorization rather
  than a custom privileged broker/helper. Authorization preflight occurs before
  long create-time verification where applicable.

V2.5.0 completed clean-host Fedora acceptance, graphical guest verification
for Fedora Workstation, Kali, and Whonix flows, and the Rust workspace test
suite.

## Supported V2.5 profiles

- `kali-lab`
- `fedora-workstation`
- `whonix-gateway`
- `whonix-workstation`

The legacy Fedora Cloud/NoCloud path remains compatibility-only and is not the
new V2.5 Fedora workflow.

## Installation

Forge V2.5.0 is installed from source; it does not ship as an RPM/DNF package.
See the [README](../../README.md),
[Fedora host setup](../FEDORA_SETUP.md), and the
[V2.5 user guide](../FORGE_V2_5_USER_GUIDE.md).

## Important behavioral boundaries

Forge manages host-side VM lifecycle, storage, topology, and durable ownership.
It does not automatically create guest accounts, configure guest credentials,
run guest package updates, or personalize desktop guests. Fedora Workstation
promotion preserves the operator-configured canonical installation; derived
VMs inherit those contents and settings.

## Upgrade and compatibility notes

V2.5.0 should be treated as a clean, explicit installation and workflow
release. This release does not provide a documented automatic V2.0-to-V2.5
migration path. Do not fabricate state or adopt resources by name; use exposed
reconciliation and recovery commands only when their exact proofs succeed.

## Known limitations

- No RPM/DNF package.
- Fedora Workstation installation is operator-assisted.
- No Disposable VM mode.
- No automatic guest provisioning, sanitization, or personalization.
- First-time acquisition and cryptographic verification of large images can be
  slow.
- The built-in Whonix pair requires the canonical instance names
  `whonix-gateway` and `whonix-workstation`; custom pair names are unsupported.

## Validation

The release passed clean-host Fedora acceptance, host-side lifecycle and safe
delete/recovery acceptance, graphical verification of supported guest paths,
formatting, workspace compilation, and workspace tests.
